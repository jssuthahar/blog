Copilot /init drafts your AGENTS.md in seconds. Every line is true. That is the problem. 📄

It describes the code: stack, folders, packages. It decides nothing. In one week on a food delivery app:
• Tuesday, an agent logs a whole order while debugging: name, phone, address.
• Wednesday, a promo is priced inside the checkout widget instead of the domain.
Nothing in the generated file said not to.

AUDIT YOUR FILE
grep -c '^## ' AGENTS.md
grep -ciE 'best practice|clean code' AGENTS.md
grep -ciE 'never|must|do not' AGENTS.md

Sections, vague lines, hard rules. Aim for zero vague lines.

THE HUMAN EDIT
1. Keep the stack and folders /init got right.
2. Name ONE state pattern, not the two it found.
3. Write the business rules word for word.
4. Add a security section: never log names, phones or addresses. debugPrint counts.

## Stage breakdown

01. **/init writes a draft** (5200ms) — Copilot scans the repo and drafts AGENTS.md from what it finds.
02. **What it cannot see** (5400ms) — Business rules and security policy are not in the code. They are in people.
03. **Tuesday: an export button** (5600ms) — An agent logs the whole order while debugging. The order holds a phone number.
04. **Wednesday: a promo** (5200ms) — The discount is calculated inside the checkout widget, not in Promo.
05. **Audit the file** (5600ms) — Count sections, vague lines, hard rules and security rules.
06. **Write the business rules** (5200ms) — Totals from Cart. Promos through Promo.discountFor. Word for word.
07. **Write the security section** (5200ms) — Never log names, phones or addresses. debugPrint counts as logging.
08. **Audit again** (5600ms) — Nine sections, zero vague lines, fifteen hard rules, four security rules.
09. **Generate, then edit** (4800ms) — Keep what /init got right. Add business rules and security by hand. Audit the file.
