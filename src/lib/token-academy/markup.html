Picture it: six everyday comparisons

Six everyday comparisons for how tokens add up, and a receipt you can print in your head.

Way 1 · What a token is

Tokens are like LEGO bricks

AI models don’t read letters or words. They read bricks: short pieces of text. A common word is one brick; a long or unusual word is several.

A handy rule: 1 token ≈ 4 letters ≈ ¾ of a word. So 100 tokens is about 75 words. Code needs more bricks, because symbols like ( and ; are bricks too.

Way 2 · Input tokens

Your request is a parcel

You write a short note. But Copilot packs a whole parcel around it so the AI can help: its rulebook, your project’s instructions, a toolbox, your earlier messages, and the code files you pointed at.

The parcel is weighed in tokens, and you pay for the whole parcel, not just your note.

Way 3 · Output tokens

The answer runs on a taxi meter

The AI writes its answer one token at a time, and the meter keeps ticking until it stops. Output tokens have a higher fare than input, about 5 times on most models.

Asking for “just the change” is a short ride. Asking for the whole file again is a long one.

Way 4 · Cached tokens

Cache is a box that’s already packed

Send a follow-up a minute later and most of the parcel is the same. The AI service keeps a recent copy, so those parts are reused instead of repacked, at about 10% of the price.

The copy expires after about an hour on most models, and changing the model mid-chat throws it away.

Way 5 · Chat history

A long chat is a snowball

The AI has no memory, so every new message re-sends the whole conversation. Message 10 carries messages 1 to 9 inside it.

Like a snowball rolling downhill, each message is bigger than the last, and the total grows fast.

The model is your courier

The same parcel costs very different amounts depending on the courier. Light models are economy: cheap and fine for simple jobs. Big reasoning models are express: great for hard problems, but up to 100× the price.

Why output is pricier

Input tokens are read together in one pass. Output tokens are produced one at a time, each needing its own pass through the model. That extra work is why output is priced about 5× higher on most models.

When does it stop?

The model keeps going until it predicts a special end token or hits a length limit. Asking for “only the changed lines” makes the end token come much sooner.

Reasoning models think first

Models with reasoning write hidden “thinking” tokens before the answer. On most models those are billed as output too, so higher reasoning effort means more output tokens.

Billed once, read many times

The model looks back at the whole sequence for every new token, but you are billed for each input token once per request and each output token once.

1 · The old model

How PRU multipliers worked

Under request-based billing, each prompt you sent in Copilot Chat (ask, edit, agent or plan mode) used one premium request, multiplied by the model’s multiplier. A cheap model might count as 0.33 of a request; a frontier model as 27. The prompt’s length didn’t matter. Agent tool calls didn’t count, only your prompts. Copilot code review used 13 per review.

2 · The change

Why GitHub moved to AI Credits

Copilot now runs long, multi-step agent sessions across whole repositories. Under PRU billing, a quick question and a multi-hour agent session could cost the same, while the real compute differed by thousands of times. GitHub said that model was no longer sustainable, and moved to billing by actual tokens at each model’s published rates.

The fix

Measured by GitHub

GitHub tracked token use in its own agentic workflows using an “effective tokens” measure (output weighted 4×, cached input 0.1×, scaled by model tier), then pruned unused MCP tools, replaced some MCP calls with the GitHub CLI, and moved suitable workflows to cheaper models.

−62%Auto-Triage Issues workflow, over 109 runs after the changes
−59%Smoke Claude workflow, partly from switching to Haiku
−43%Security Guard workflow

A 40-tool GitHub MCP server can add 10–15 KB of tool schema to every turn; pruning unused tools saved 8–12 KB per call. Source: GitHub blog, “Improving token efficiency in GitHub Agentic Workflows”.

Instructions, skills & hooks

Copilot lets you add knowledge and automation to every session. Each piece enters the model’s context at a different moment, so each has a different token cost.

When each one costs tokens

FeatureWhere it livesWhen it is in the requestHow to keep it cheap
Custom instructions.github/copilot-instructions.md, AGENTS.mdEvery chat and agent request in the repoA short map: stack, build and test commands, real pitfalls
Path-specific instructions.github/instructions/*.instructions.mdOnly when files matching its applyTo pattern are involvedMove language- or folder-specific rules here
Prompt files.github/prompts/*.prompt.mdOnly when you run that promptSave your best focused prompts for the team
Agent skills.github/skills/<name>/SKILL.mdLoaded when relevant to the taskPut long how-tos here instead of in instructions
Custom agents.github/agents/*.agent.mdWhile that agent is selectedGive each agent only the tools it needs
MCP toolsMCP server configurationEvery enabled tool’s definition, on every requestEnable only the toolsets the task needs

Skills follow the open Agent Skills standard, where a skill’s short description is visible to the agent and its full instructions are read when the task calls for it. Hooks are supported in Copilot CLI and the cloud agent.

Agent comparison

A map saves the agent from exploring

Without guidance, an agent spends its first calls exploring: reading folders and files to guess your framework, test command and style, and then fixing its wrong guesses.

A short .github/copilot-instructions.md rides along on every request, so it costs a few hundred tokens each time, but it removes the exploring. A skill is extra know-how (for example “how we write unit tests”) that is loaded only when the task needs it.

Too much is also a problem: a 6,000-token instructions file is paid on every single call.

What it means for youKeep instructions short and true; put detailed how-tos in skills or prompt files.

📘 Instructions: the map

Costs a few hundred tokens on every request. Saves the agent from exploring folders to learn your stack, commands and conventions. The single best first step.

🤖 Custom agents: the right specialist

Each agent gets only the tools it needs (fewer tool definitions per call), its own focused instructions, and can run on a model sized for the job: a reasoning model to plan, a lighter one to write tests.

🧰 Skills: know-how on demand

Only a short description sits in context. The full steps load when the task matches, so detailed procedures don’t ride along on every request, yet the agent follows them first time.

🪝 Hooks: automatic guard rails

Commands that run outside the model at set moments. They can block wasteful tool calls (reading generated files) and shrink noisy tool output, so less text is re-sent on every later call.
