Code-complete in week 9. Shipped in week 14. Not one of those five weeks was code. 🧭

A Flutter and Firebase app, one AI coding agent, a green build. Then:
Week 10: Firestore rules let any signed-in user read any order.
Week 11: a package under a licence the store build cannot ship. Four days to remove.
Weeks 12-14: no changelog, swallowed errors, analytics in 2 of 11 screens, buttons TalkBack reads as "button".

An AI coding agent is one developer, not a team. When the coding half speeds up, the other half becomes the schedule.

The fix:
🪝 If a script can answer it yes or no, it is a hook. The reference app has 14 hook checks.
🧭 Judgement gets a narrow agent. Build four first: architect, code review, testing, security.

## Stage breakdown

01. **Code-complete, week 9** (5200ms) — One coding agent, a green build and every test passing.
02. **Week 10: the rules** (5400ms) — Firestore rules from week two: any signed-in user reads any order.
03. **Week 11: one licence** (5600ms) — A package the store build cannot ship, spread into three features.
04. **Weeks 12 to 14** (5200ms) — No changelog, swallowed errors, analytics in 2 of 11 screens, unlabelled buttons.
05. **Agent or hook?** (5400ms) — If a script can answer it yes or no, it is a hook. Judgement is an agent.
06. **14 hook checks** (5200ms) — pre-commit: 10 checks. pre-push: 4. Each one a script.
07. **Four agents first** (5400ms) — Solution architect, code review, testing, security. In that order.
08. **The next release** (5800ms) — The bad licence fails the push the day it is added. Code-complete week 9, shipped week 10.
09. **One agent is a developer, not a team** (4800ms) — Agents for judgement. Hooks for rules. Start with four.
