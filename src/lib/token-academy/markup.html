Everything you send to Copilot and everything it writes back is counted in tokens. Since June 1, 2026, those tokens are what your organization pays for, in GitHub AI Credits. Start with the one-line idea below, then follow the numbered steps.

Way 1 · What a token is

Tokens are like LEGO bricks

AI models don’t read letters or words. They read bricks: short pieces of text. A common word is one brick; a long or unusual word is several.

A handy rule: 1 token ≈ 4 letters ≈ ¾ of a word. So 100 tokens is about 75 words. Code needs more bricks, because symbols like ( and ; are bricks too.

Way 3 · Output tokens

The answer runs on a taxi meter

Asking for “just the change” is a short ride. Asking for the whole file again is a long one.

Way 4 · Cached tokens

Cache is a box that’s already packed

Send a follow-up a minute later and most of the parcel is the same. The AI service keeps a recent copy, so those parts are reused instead of repacked, usually at 10% of the input price or less.

The copy expires after a period of inactivity that each provider sets, and changing the model mid-chat throws it away.

Way 6 · Choosing a model

The model is your courier

The same parcel costs very different amounts depending on the courier. Light models are economy: cheap and fine for simple jobs. Big reasoning models are express: great for hard problems, but up to 100× the price.

Not sure? Auto picks a courier for you, and on paid plans takes 10% off in Copilot Chat and the cloud agent.

Why output is pricier

Input tokens are read together in one pass. Output tokens are produced one at a time, each needing its own pass through the model. Every model on GitHub’s list prices output higher than input: 3–8× (5× on most).

When does it stop?

The model keeps going until it predicts a special end token or hits a length limit. Asking for “only the changed lines” makes the end token come much sooner.

Reasoning models think first

Models with reasoning write hidden “thinking” tokens before the answer. OpenAI and Anthropic bill them as output, and you pay for all of them even though you don’t see them; on OpenAI they also take up room in the context window. Higher reasoning effort means more of them.

Billed once, read many times

The model looks back at the whole sequence for every new token, but you are billed for each input token once per request and each output token once.

Continue the chat, or start fresh?

Every message re-sends the whole chat. Sometimes that is the cheapest way to work, and sometimes the most expensive. Here is how to tell, and how to carry your context over when you do start again.

Illustrative model: the cache holds everything sent before the current message until you take a long break; a new chat starts with a 1,000-token summary and pays full price on its first message. Real caching varies by model.

When to continue, and when to start fresh

✓ Continue the chat when

  • It is a quick follow-up on the same task
  • The answer depends on what was just said
  • You are still working on the same files
  • You are on the same model, with the same settings

↻ Start a new chat when

  • The topic changes
  • You are back after a break: caches expire after a period of inactivity set by each provider
  • The chat has grown long, or the answers start to drift
  • You want a different model: the cache is lost anyway
  • The history is full of logs and files you no longer need
How long does the cache last? GitHub doesn’t publish Copilot’s cache lifetime, so here is what the providers document. Anthropic keeps a cached prefix for 5 minutes, refreshed each time it is reused (a 1-hour option costs more to write). OpenAI keeps it for 30 minutes on GPT‑5.6 and later, and for about 5–10 minutes of inactivity, up to an hour, on earlier models. Very short prompts aren’t cached at all: the minimum is 512 to 4,096 tokens depending on the model.

Tip: new task, new chat

Make it a habit: when you finish one task and start another, clear the chat first. Saved files, custom instructions and memory are kept; only the conversation is dropped.

Why clear it? The model remembers nothing between messages, so Copilot re-sends the whole chat with every new one.
  • You pay for history you no longer need. With the defaults in the calculator above (12,000 tokens of starting context and 15 messages of 3,000 tokens each), every new message carries about 57,000 tokens. In a fresh chat it carries about 12,000 plus your question: roughly 45,000 fewer input tokens on every message that follows.
  • On a new topic, none of that history helps. Fresh from the cache it is cheap, but it is still sent, and after a break the cache has expired and it is billed at full input price.
  • Answers get better. Old files, logs and decisions from the last task stay in front of the model and pull its answers toward that task. A clean chat answers the question you actually asked.
  • You stay further from the limits. A shorter context keeps you under the context window and the long-context price line, so Copilot does not have to compact or trim mid-task.
💻 VS CodeType /clear, select New Chat (+), or press Ctrl+N (⌘N on macOS). Note: /new here scaffolds a project, it does not clear the chat.
⌨️ Copilot CLI/clear starts a new conversation (/new and /reset do the same). /compact keeps going on a summary instead.

The fix

Measured by GitHub

GitHub tracked token use in its own agentic workflows using an “effective tokens” measure (output weighted 4×, cached input 0.1×, scaled by model tier), then pruned unused MCP tools, replaced some MCP calls with the GitHub CLI, and moved suitable workflows to cheaper models.

A 40-tool GitHub MCP server can add 10–15 KB of tool schema to every turn; pruning unused tools saved 8–12 KB per call. Source: GitHub blog, “Improving token efficiency in GitHub Agentic Workflows”.

Instructions, skills & hooks

Copilot lets you add knowledge and automation to every session. Each piece enters the model’s context at a different moment, so each has a different token cost.

Agent comparison

A map saves the agent from exploring

Without guidance, an agent spends its first calls exploring: reading folders and files to guess your framework, test command and style, and then fixing its wrong guesses.

A short .github/copilot-instructions.md rides along on every request, so it costs a few hundred tokens each time, but it removes the exploring. A skill is extra know-how (for example “how we write unit tests”) that is loaded only when the task needs it.

Too much is also a problem: a 6,000-token instructions file is paid on every single call.

What it means for youKeep instructions short and true; put detailed how-tos in skills or prompt files.

📘 Instructions: the map

Costs a few hundred tokens on every request. Saves the agent from exploring folders to learn your stack, commands and conventions. The single best first step.

🤖 Custom agents: the right specialist

Each agent gets only the tools it needs (fewer tool definitions per call), its own focused instructions, and can run on a model sized for the job: a reasoning model to plan, a lighter one to write tests.

🧰 Skills: know-how on demand

Only a short description sits in context. The full steps load when the task matches, so detailed procedures don’t ride along on every request, yet the agent follows them first time.

🪝 Hooks: automatic guard rails

Commands that run outside the model at set moments. They can block wasteful tool calls (reading generated files) and shrink noisy tool output, so less text is re-sent on every later call.
